# AI Model Integration: AI Agent Control Actions List

## 1. Action Trigger Mechanism

The AI Agent receives greenhouse sensor data after it has passed through the **BCD arithmetic error detection module** and the **sensor data quality checking layer**. The input data may include temperature, humidity, soil moisture, light intensity, and water flow values.

Before generating any control action, the system first checks whether the sensor data contains:

* Invalid BCD codes
* Decimal arithmetic errors
* Overflow errors
* Abnormal or out-of-range sensor values
* Sensor fault warnings

Only validated and reliable sensor data will be passed to the **Agentic RAG module**. The RAG engine retrieves relevant agricultural knowledge, technical procedures, and greenhouse control guidelines. The AI Agent then combines the validated sensor data with retrieved knowledge to generate suitable control commands for simulated greenhouse actuators.

If the BCD error detection module reports invalid or unreliable data, the AI Agent must not directly execute automatic control commands. Instead, it must generate a warning message and request sensor checking or data revalidation.

## 2. Specific Actuator Control Actions

### 2.1 Ventilation Control

The AI Agent outputs a command to activate ventilation or cooling fans when temperature or humidity exceeds the safe threshold.

**Example action:**

```text
ACTION: TURN_ON_FAN
REASON: Temperature or humidity is above the safe range.
```

This action helps reduce excessive heat or humidity inside the greenhouse and protects plants from unsuitable environmental conditions.

### 2.2 Irrigation Control

The AI Agent outputs a command to activate the water pump when soil moisture is below the required threshold.

The command should include a specific water volume parameter in milliliters.

**Example action:**

```text
ACTION: ACTIVATE_WATER_PUMP
VOLUME: 500 ml
REASON: Soil moisture is below the recommended level.
```

This action helps maintain proper soil moisture and prevent plant stress caused by insufficient water.

### 2.3 Lighting Control

The AI Agent outputs a command to turn on artificial lighting when light intensity is lower than the required level for plant growth.

**Example action:**

```text
ACTION: TURN_ON_GROW_LIGHT
REASON: Light intensity is below the suitable threshold.
```

If the light intensity is already sufficient, the AI Agent should avoid activating unnecessary lighting to save energy.

### 2.4 Sensor Error Warning

If the BCD arithmetic error detection module detects invalid decimal sensor data, the AI Agent must generate a warning instead of sending an actuator command.

**Example action:**

```text
ACTION: SENSOR_ERROR_WARNING
REASON: Invalid BCD code detected in the sensor data.
```

This prevents the greenhouse system from making unsafe decisions based on corrupted or invalid sensor readings.

### 2.5 Overflow or Abnormal Data Alert

If the system detects overflow during decimal sensor calculation or identifies abnormal values outside the expected physical range, the AI Agent must stop automatic control and notify the user.

**Example action:**

```text
ACTION: DATA_VALIDATION_ALERT
REASON: Overflow or abnormal decimal value detected during sensor data processing.
```

This action improves system reliability and reduces the risk of incorrect greenhouse control.

## 3. Action Output Constraints

Every control command generated by the AI Agent must follow strict reliability and explainability requirements.

Each output must include:

1. **Action command**
   The exact actuator action, such as turning on a fan, activating a water pump, or turning on a grow light.

2. **Validated sensor data**
   The sensor values used to make the decision must be shown clearly.

3. **BCD validation status**
   The output must state whether the BCD data is valid or whether an error was detected.

4. **Reasoning text**
   The AI Agent must explain why the action is needed.

5. **Retrieved reference evidence**
   The AI Agent must include a quote or reference from the retrieved agricultural knowledge document to support the decision.

6. **Safety rule**
   If the sensor data is invalid, corrupted, or unreliable, the AI Agent must not execute automatic control commands.

## 4. Example AI Agent Output

```text
ACTION: ACTIVATE_WATER_PUMP
VOLUME: 500 ml

SENSOR DATA:
- Soil moisture: 23%
- Temperature: 31°C
- Humidity: 65%

BCD VALIDATION STATUS:
Valid BCD input. No overflow detected.

REASONING:
The soil moisture value is below the recommended threshold. Therefore, irrigation is required to prevent plant water stress.

REFERENCE EVIDENCE:
According to the retrieved greenhouse irrigation guideline, soil moisture below the safe range requires additional watering to maintain suitable plant growth conditions.
```

## 5. System Safety Behavior

If invalid BCD data or arithmetic errors are detected, the AI Agent must stop the control action and return an alert.

```text
ACTION: SENSOR_ERROR_WARNING

BCD VALIDATION STATUS:
Invalid BCD code detected.

REASONING:
The sensor value cannot be trusted because the decimal data contains an invalid BCD representation. Automatic actuator control is blocked to prevent unsafe greenhouse operation.

RECOMMENDATION:
Check the sensor module, data transmission process, or BCD arithmetic processing unit before retrying the control action.
```

## 6. Role in the Proposed System

This AI Agent control mechanism supports the proposed topic **BCD Arithmetic Error Detection for Reliable Sensor Data Processing in AIoT Smart Greenhouse Systems**.

The key idea is that greenhouse control decisions should only be made after sensor data has been validated. By combining BCD arithmetic error detection, sensor data quality checking, Agentic RAG, and explainable AI control actions, the system can improve the reliability, safety, and transparency of smart greenhouse management.
